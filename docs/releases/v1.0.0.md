# Ultra Next Template v1.0.0 — proposed release notes

Draft for review; no release or tag has been published.

Ultra Next Template is a production-minded, opinionated, domain-agnostic frontend foundation. The initial application domain is intentionally empty; the technical infrastructure is ready to extend.

## Included

- **Core stack:** Next.js 16.4 App Router, React 19.3, strict TypeScript, Tailwind CSS 4, source-owned shadcn/ui primitives, TanStack Query/Table, nuqs, React Hook Form and Zod.
- **API and authentication boundaries:** typed Axios requests, schema-validated responses, cancellation, normalized errors, coordinated refresh, provider-neutral bearer/cookie adapters, query keys, pagination and guarded optimistic rollback. Applications supply real contracts, identity providers and server authorization.
- **Localization and UI:** English/Bosnian messages and navigation, localized dates and metadata, canonical/alternate URLs, sitemap/robots/manifest, theme switching, reusable UI states, SVG icons and Storybook.
- **Quality:** frozen pnpm installs, formatting, ESLint, type checks, unit coverage thresholds, development/production Playwright, accessibility, Linux visual references and Lighthouse budgets in GitHub Actions.
- **Security hardening:** validated public URLs, CSP/security headers, constrained API destinations and request options, redirect/proxy restrictions for authenticated requests, bounded refresh waits and privacy-safe error reporting. The `fast-uri` transitive advisory is remediated with compatible patch `3.1.8`.
- **Template experience:** GitHub template-first onboarding, preserved interactive/noninteractive setup CLI, idempotent identity/environment personalization, and an isolated derived-application smoke check that verifies an independent frozen install and localized production output.

## Requirements and integration work

Use Node 24.x (at least 24.15.0; `.nvmrc` tracks 24) and pnpm 11.19.0. Public environment variables are embedded during builds. Install Playwright Chromium for browser checks and use Docker for canonical Linux visual checks on other platforms.

No database, authentication service, business feature, deployment pipeline or monitoring vendor is selected. Integrate these for your application, enforce authorization and cookie/CSRF/CORS policy on the backend, replace placeholder branding, and add domain tests. Generated repositories own their security contacts, settings, updates and release process. Retain the MIT copyright and permission notice.

## Known limitations and publication gates

- Remaining development-tool advisories and peer-range mismatches are documented in the [dependency assessment](../dependency-assessment.md); green production audit CI does not clear those risks.
- Visual references target the default template identity on Linux and need deliberate updates after branding changes. Lighthouse score/LCP are warnings; CLS, blocking-time and byte budgets are enforced.
- Setup restores files after ordinary write failures, but is not a crash-safe multi-file transaction; avoid concurrent edits and inspect after interruptions.
- Authentication/storage/provider behavior, deployment configuration and domain authorization require application-level validation. Telemetry deliberately excludes raw messages and stacks.
- Publication remains gated on owner activation of GitHub's template setting, the real **Use this template** test, final Actions results and advisory disposition. Follow the [release checklist](../release-checklist.md).
